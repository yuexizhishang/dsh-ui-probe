# DSH 图形界面插件测试工具（dsh-ui-probe）

**在真实运行的 DeepSeek Harness 界面里自动测试插件页面。**

UI 探针让 DeepSeek Harness 在做图形化界面插件时，能够自己把界面切换到目标插件页面、读取信息、验收调试插件功能。

具体功能有：读取插件界面的布局、文字与样式（尺寸、颜色、间距），点击页面按钮，往输入框填内容，等待异步结果出现，抓取控制台报错，以及量出每一步花了多久。

在调用完之后，插件会自动回到原对话界面，让对话继续工作。

---

## 安装

**方式一：从 DeepSeek Harness 桌面端安装（推荐）**

在 DeepSeek Harness 的「插件 → 添加插件」里粘贴下面这行，点安装：

```text
github:yuexizhishang/dsh-ui-probe
```

等价的完整地址是 `https://github.com/yuexizhishang/dsh-ui-probe`。

**方式二：从 npm 安装**

在 DeepSeek Harness 的「插件 → 添加插件」里粘贴下面这行，点安装：

```text
@yuexizhishang/dsh-ui-probe
```

装的是预构建好的版本，不需要编译。

**方式三：下载后从本地安装**

```powershell
git clone https://github.com/yuexizhishang/dsh-ui-probe.git
```

然后把克隆下来的目录路径告诉对话，让 AI 帮你安装即可。

安装完成后如果提示需要重启，重启一次 DeepSeek Harness 即可。

**装完不用配置任何东西。** 插件自带一套发现机制：对话里会多出 `ui_probe` 和 `ui_page` 两个工具，技能列表里会出现「dsh-ui-probe」的指南，模型读到描述就会知道什么时候该用它。卸载插件时这些一起消失，不往系统里留文件。

## 用起来是什么样

直接对对话说一句就行，比如：

> 验收一下便签插件，看一下界面和插件功能有没有问题。

对话会按三步走：

| 步骤 | 做什么 |
|---|---|
| **打开** | 切到目标插件页面：知道面板 id 就直接切过去（不点侧栏），不知道就按侧栏里的名字点；记住你原来的对话，供之后返回 |
| **操作** | 一步一个动作，也可以一次交一整份动作清单；能点击、按文字找元素、读计算样式、填表单、按键、等结果出现、页面快照 |
| **收尾** | 返回全程时间线 + 页面快照 + 每一步的耗时 + 控制台报错，然后自动回到你的对话 |

它能做的动作：

- **读真实界面**：元素的实际尺寸、位置，以及字号、颜色、内外边距、圆角、不透明度等计算样式
- **点按钮**：按可见文字或 CSS 选择器定位；文字出现在聊天记录里时，可以限定只在某个容器内找。按文字点只会真的落到控件上（按钮、链接、带 role 或可聚焦的元素）——如果这几个字只出现在段落里，会明确报错并列出附近能点的控件，而不是"点了没反应却报成功"
- **看点击有没有反应**：每次点击后附带界面变更的条数、新增/移除了多少节点，以及焦点、滚动、标题有没有变；"点了没反应"和"点到了别的元素"都会直接露出来
- **按编号操作**：取一次快照后，页面上的控件会带上编号（`e1`、`e2`…），之后直接按编号点击或读取，不会因为两处文字一样而点错
- **填表单**：普通输入框、文本域、富文本编辑器都支持，写完会回读校验，写不进去会明确报失败而不是假装成功
- **按键盘**：回车、Esc、退格等
- **等异步**：轮询等待某个元素出现，适合"加载中→出列表""点完弹提示"这类延迟生效的效果
- **抓报错**：控制台报错随每一步的结果一起返回，标出是哪个面板报的、面板名是从哪儿认出来的；图片、脚本、样式加载失败也会记录下来
- **量耗时**：每一步给出总耗时、点击到界面响应的耗时、等待耗时，以及执行期间有没有长任务卡住界面

如果你只想快速看一眼某个面板长什么样，还可以让它打开、读一次、立刻回来，不用走完整流程。

**不用担心它赖着不走**：验收结束会主动返回；中间 30 秒没有新动作会自动收尾（这一步是否还在进行，以实际返回为准）；页面意外刷新后也会照着记录的起点回到原对话。

## 跑一整串动作

要测的流程通常不止一步：点开菜单 → 填名字 → 点保存 → 等列表里出现新条目。逐个动作来回一轮，既慢又容易在中途丢掉状态。

插件支持**一次交一整份清单**：

| 清单里能写 | 含义 |
|---|---|
| 点击 | 按文字、选择器或编号点一个元素 |
| 等待出现 | 等到某个元素出现再继续（另有固定等待多久） |
| 读取 | 读出某个元素的几何与计算样式 |
| 快照 | 给出当前可见的标题与按钮清单，并刷新元素编号 |
| 输入 | 往输入框、文本域或富文本里写内容并回读校验 |
| 按键 | 回车、Esc、退格等 |

几点约定：

- **按顺序执行，结果统一返回**：所有步骤的结果、每一步的耗时、期间出现的控制台报错，都在同一次返回里给齐，不用一步一问。
- **失败可以停，也可以继续**：默认遇到执行不了的步骤就停，剩下的跳过并说明原因；也可以让它跑完所有步骤再一起报告。
- **每一步单独计时**：默认一步最多等 90 秒，超时会明确告诉你"这一步超时了、超时多少毫秒"，不会假装成功。需要更长或更短的等待，可以让对话按步指定（1 秒到 10 分钟）。
- **每一步都能定位到"哪一步失败了"**：返回里带步骤序号与动作名，出问题时不用从头重录。

## 数值怎么读

插件只给事实，不替你判"通过 / 不通过"——那个结论由对话结合你的要求来下。报告里的数字分别是：

| 字段 | 含义 |
|---|---|
| 总耗时 | 这一步从开始到结果返回花了多久 |
| 交互耗时 | 点击之后到界面渲染出下一帧花了多久，用来判断点完是否"卡了一下" |
| 等待耗时 | 等元素出现实际等了多久；没等到会写超时时长 |
| 长任务 | 执行期间超过 50 毫秒、会阻塞界面的脚本任务数量与累计时长 |
| 变更条数 | 点击后 DOM 发生了几次变更、新增/移除了多少节点；全为 0 说明这次点击没有带来任何界面变化 |
| 焦点 / 滚动 / 标题变化 | 点击后输入焦点是否转移、视图是否滚动、窗口标题是否变化 |
| 报错面板 | 报错发生时屏幕上是哪个面板，用于把别的插件的报错区分开 |
| 归因依据 | 面板名是从哪里取到的（可见标题 / 面板内标题 / 文档标题 / 对话），来源不同可信度不同 |
| 资源失败 | 图片、脚本、样式、媒体加载失败时记录的类型与地址（浏览器只给地址，不给失败原因） |

## 插件设置页

「设置」的侧栏里会多出一栏「UI 探针」，提供三件事：

| 功能 | 说明 |
|---|---|
| 检查更新 | 打开即自动比对 GitHub 上的版本，显示当前版本、最新版本和状态；网络不通或仓库不可达时如实报错，不会假装"已是最新" |
| 更新并安装 | 有新版才可点；已经是最新则跳过，不会重复安装 |
| 卸载插件 | 二次确认后卸载；**只移除这个插件本身，不删除任何你自己的文件或仓库** |

插件本身**不会去打开设置面板**。

## 安全边界

**设置、账号、余额、充值和账号菜单，对自动化完全封闭。**

- 账号菜单按钮不会被点开，菜单内的任何操作一律拒绝；
- 设置面板内的点击、输入、按键同样一律拒绝；
- 万一某个操作意外打开了设置面板或账号菜单，会立刻关掉并报告"已拒绝"；
- 唯一例外是插件自己的设置页（版本 / 更新 / 卸载那一栏）。

## 已知限制

| 做不到 | 原因 |
|---|---|
| 不知道面板 id 时自动切面板 | 槽位接口没有"列出所有面板"的方法，id 只能从插件源码或注册处得知；未知时按侧栏名字点 |
| Canvas / 自绘编辑器里的输入 | 只支持标准输入框、文本域和普通富文本 |
| 同时跑多个验收任务 | 一次只能有一个任务，后到的会排队 |
| 元素编号长期有效 | 页面内容一变，编号就作废，需要重新取一次快照；按旧编号操作会明确报错，不会点到别处 |
| 精确到控件级的报错归因 | 报错只能标到"哪个面板"，因为控制台报错本身不带控件信息；面板标题相同或为空时只能标成页面级 |
| 资源失败的具体原因 | 浏览器只给"加载失败 + 地址"，拿不到状态码或错误类型 |

**不需要截图也能验收**：插件拿到的是尺寸、样式、文字、耗时和控制台报错这些可核对的值，比看截图更准。要一张图给别人看观感，用系统自带截图即可（Windows `Win+Shift+S`、macOS `Shift+Cmd+4`）。
